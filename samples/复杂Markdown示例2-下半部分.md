# 复杂Markdown示例2-Agent智能体知识（下半部分）

## 四、常见 Agent 架构

不同 Agent 架构适合不同复杂度的任务。简单工作流不需要过度设计，复杂任务才需要更强的规划和多角色协作。

### 1. ReAct 模式

ReAct 是 Reasoning and Acting 的组合，意思是边推理边行动。Agent 先产生一个想法，再选择工具，观察结果后继续推理。
- 优点
- 实现简单
- 适合工具调用和快速排错
- 每一步都容易追踪
- 缺点
- 长任务容易偏离目标
- 计划可能不够全局
- 容易陷入反复尝试

### 2. Plan-and-Execute

Plan-and-Execute 先制定完整计划，再由执行器逐步完成。它适合步骤明确、流程较长的任务。
- 优点
- 全局结构清楚
- 不容易遗漏大步骤
- 适合文档生成、代码迁移
- 缺点
- 初始计划可能不符合实际
- 环境变化时需要重新规划

### 3. Reflexion 模式

Reflexion 强调反思。Agent 执行失败后，不只重试，还会总结失败原因，并把经验用于下一次尝试。Reflexion 强调反思。Agent 执行失败后，不只重试，还会总结失败原因，并把经验用于下一次尝试。这种模式适合代码调试、测试修复和数据分析。关键是反思结果必须来自真实错误信息，不能凭空编造原因。

### 4. 多智能体协作

多智能体系统会把任务分给不同角色，例如规划者、执行者、审查者和检索者。每个Agent 专注一类任务，最后由协调者汇总。
- 规划者
- 拆解任务
- 排定顺序
- 检索者
- 查文档
- 查代码
- 查外部资料
- 执行者
- 修改文件
- 运行命令
- 审查者
- 检查质量
- 发现安全风险
- 核对验收标准

多智能体并不一定比单智能体更好。角色越多，通信成本和出错环节也越多。第一版产品通常应优先使用稳定的单 Agent 工作流，确有必要后再拆分角色。

## 五、Agent 开发中的关键问题

### 1. 可靠性

模型输出具有一定不确定性，因此不能把模型回答直接当成可信指令。系统应该使用结构化参数、服务端校验、测试用例和权限控制来提高可靠性。

### 2. 上下文限制

即使模型上下文窗口很大，也不应该把所有文件都塞进去。无关信息会浪费 Token，也会干扰模型判断。更好的方式是先检索，再把最相关的片段放入上下文。

### 3. 成本控制

Agent 可能在一个任务中进行多轮模型调用和工具调用，成本会比普通聊天高。可以通过缓存检索结果、减少重复输入、限制循环次数和使用小模型处理简单步骤来降低成本。
- 只把必要信息发给模型
- 避免重复读取大文件
- 给工具调用设置次数上限
- 对失败重试设置边界
- 记录每次任务消耗的 Token

### 4. 可观测性

Agent 出错时，需要知道它当时看到了什么、想了什么、调用了哪个工具、工具返回了什么。没有日志和追踪信息，就很难排查问题。Agent 出错时，需要知道它当时看到了什么、想了什么、调用了哪个工具、工具返回了什么。没有日志和追踪信息，就很难排查问题。需要重点记录任务状态、工具名称、耗时、错误码、模型版本和 Token 用量。用户隐私和密钥不能写入日志。

### 5. 权限与安全

Agent 拥有工具能力后，安全边界非常重要。文件系统、数据库、网络请求和外部消息都应该分级授权。对于不可逆操作，应要求用户明确确认。
- 不允许读取无关敏感文件
- 不允许把密钥发送到外部
- 不允许未经确认删除数据
- 不允许绕过项目规则
- 不允许执行来源不明的危险命令

### 6. 效果评测

Agent 的效果不能只凭一次成功演示判断。应该准备多组任务，测试成功率、平均步骤数、成本、失败恢复能力和是否遵守权限。

## 六、学习 Agent 开发的路线

学习 Agent 不应该只停留在提示词层面，还需要理解 API、工具、数据、工作流和工程部署。
- 第一阶段：理解大模型 API
- 消息结构
- 系统提示词
- JSON 输出
- 温度和 Token
- 第二阶段：掌握工具调用
- 函数参数
- 工具返回值
- 错误处理
- 调用权限
- 第三阶段：学习 RAG
- 文档切分
- 向量嵌入
- 相似度检索
- 引用来源
- 第四阶段：实现工作流
- 状态管理
- 任务拆解
- 重试机制
- 人工确认
- 第五阶段：工程化部署
- 日志追踪
- 成本统计
- 安全隔离
- 性能评测

初学者可以先做一个“文档问答助手”，再扩展成“能读取文件并生成思维导图的 Agent”，最后加入工具调用、任务状态和人工审核。

## 七、Agent 的典型应用场景

- 编程助手
- 阅读代码
- 修复错误
- 编写测试
- 生成提交说明
- 数据分析助手
- 读取表格
- 统计指标
- 绘制图表
- 输出结论
- 办公助手
- 总结会议记录
- 生成周报
- 整理待办事项
- 检查文档格式
- 教育助手
- 根据知识图谱出题
- 解释学生错误
- 生成分层练习
- 跟踪学习进度
- 客服助手
- 检索知识库
- 判断问题类型
- 调用订单系统
- 升级人工处理

在本项目中，Agent 的第一版不需要完全自主行动，而是应该采用固定工作流：读取Markdown、识别变化、调用 AI、校验结果、生成思维导图预览、用户确认后再发布。这样比让模型自由操作整个系统更稳定，也更容易保证数据安全。
