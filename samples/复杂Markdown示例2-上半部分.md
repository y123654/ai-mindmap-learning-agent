## Agent 智能体基础知识

## 一、什么是 Agent

Agent 通常翻译为“智能体”，是一种能够理解目标、感知环境、制定计划、调用工具并根据反馈持续调整行为的人工智能系统。与只能进行单轮问答的聊天机器人相比，Agent更强调自主完成一串连续任务。Agent 通常翻译为“智能体”，是一种能够理解目标、感知环境、制定计划、调用工具并根据反馈持续调整行为的人工智能系统。与只能进行单轮问答的聊天机器人相比，Agent更强调自主完成一串连续任务。一个实用的 Agent 不只是回答“应该怎么做”，还可以在获得授权后真正执行任务，例如检索资料、读写文件、运行代码、调用接口、检查执行结果，并在发现错误后重新尝试。

### 1. Agent 的基本能力

- 感知
- 接收用户输入
- 读取文件或数据库
- 获取网页、日志和工具返回结果
- 思考
- 理解任务目标
- 拆解复杂问题
- 判断下一步行动
- 行动
- 调用搜索工具
- 执行代码
- 操作文件
- 请求外部 API
- 记忆
- 保存当前任务上下文
- 记住用户偏好
- 引用历史执行结果
- 反思
- 检查执行结果
- 发现错误原因
- 调整后续计划

感知、思考、行动和反思会在任务执行过程中循环出现。Agent 每执行一步，都应该观察工具返回的结果，再决定是否继续、修正或停止。

### 2. Agent 与普通聊天机器人的区别

普通聊天机器人主要根据用户问题生成文本回答，适合解释概念、润色文字和提供建议。普通聊天机器人主要根据用户问题生成文本回答，适合解释概念、润色文字和提供建议。Agent 则更像一个可以工作的助手，它不仅会说，还能在安全边界内使用工具完成具体操作。
- 普通聊天机器人
- 主要依赖对话上下文
- 通常一次生成一个回答
- 工具调用能力较弱
- 不负责持续跟踪任务结果
- Agent
- 能把大任务拆成多个小步骤
- 能调用工具并读取返回结果
- 能根据错误进行重试
- 能在较长任务中维护状态
- 能在最终完成前进行自我检查

例如，用户要求“分析一个文件夹里的销售数据，并生成报告”。普通机器人可能告诉用户应该怎么分析；Agent 则可以读取表格、运行统计代码、生成图表、检查结果，最后写出报告。

## 二、Agent 的核心组成

Agent 通常由模型、记忆、规划、工具、执行器和安全策略几个部分组成。不同框架的命名可能不同，但核心思想基本一致。

### 1. 大语言模型

大语言模型是 Agent 的“大脑”，负责理解自然语言、推理、生成计划、组织答案和判断工具参数。模型本身并不直接拥有真实世界的执行能力，它需要通过外部工具才能读写文件、访问网络或运行程序。大语言模型是 Agent 的“大脑”，负责理解自然语言、推理、生成计划、组织答案和判断工具参数。模型本身并不直接拥有真实世界的执行能力，它需要通过外部工具才能读写文件、访问网络或运行程序。模型能力会直接影响 Agent 的稳定性。推理能力越强，越容易理解复杂目标；指令遵循能力越强，越容易按照规定格式调用工具；上下文窗口越大，能同时参考的信息越多。

### 2. 记忆系统

记忆系统让 Agent 能保存任务过程中需要反复使用的信息。没有记忆的 Agent 很容易在多步任务中忘记前面已经做过什么。
- 短期记忆
- 当前对话内容
- 当前任务目标
- 最近一次工具返回
- 工作记忆
- 已完成步骤
- 中间变量
- 当前计划和待办事项
- 长期记忆
- 用户长期偏好
- 项目规则
- 历史任务摘要
- 常用知识库

长期记忆通常需要借助数据库、向量检索或文件系统实现。模型不能无条件相信历史记忆，因为旧信息可能已经过期，重要决策前应该重新读取最新数据。

### 3. 规划模块

规划模块负责把复杂目标拆成可以执行的步骤。对于简单问题，Agent 可以直接回答；对于复杂任务，则需要先制定路线，再逐步执行。
- 理解最终目标
- 找出缺少的信息
- 把任务拆成小步骤
- 判断哪些步骤需要工具
- 设置检查点
- 根据反馈动态调整计划

规划并不是一次性完成的。Agent 在执行过程中可能发现文件不存在、接口报错、权限不足或测试失败，这时就需要重新规划。

### 4. 工具调用

工具是 Agent 与外部世界交互的接口。模型生成调用参数，系统负责真正执行工具，并把结果返回给模型。
- 文件工具
- 读取文件
- 创建文件
- 修改文件
- 列出目录
- 搜索工具
- 搜索网页
- 检索知识库
- 查询内部文档
- 代码工具
- 运行测试
- 执行脚本
- 安装依赖
- 数据工具
- 查询数据库
- 读取表格
- 生成图表
- 协作工具
- 发送消息
- 创建任务
- 调用业务系统 API

工具必须有清楚的入参、出参和权限边界。对于删除文件、发送消息、修改数据库等高风险操作，系统通常需要二次确认。

### 5. 执行器与安全策略

执行器负责把模型提出的动作真正运行起来。安全策略则决定哪些动作允许执行、哪些动作需要用户确认、哪些动作必须禁止。
- 只读操作风险较低
- 查看文件
- 查询数据
- 运行无副作用的测试
- 写入操作需要谨慎
- 修改代码
- 保存文件
- 更新数据库
- 高危操作需要确认
- 删除文件
- 发送外部消息
- 支付或下单
- 修改权限配置

安全策略不能只依赖模型自觉遵守，后端系统也要进行真实校验。即使模型输出了错误指令，执行层也应该能拦截。

## 三、Agent 的典型工作流程

Agent 执行任务时，通常会在“思考、行动、观察、修正”几个阶段之间循环，直到任务完成或确认无法继续。

### 1. 接收目标

用户首先提出目标，例如“修复这个项目的登录问题”。Agent 需要识别任务范围、涉及文件、验收标准和限制条件。如果目标不清晰，应该先提问，而不是随意猜测。

### 2. 收集上下文

Agent 会读取项目文档、代码文件、错误日志、测试结果和相关配置。对于大型项目，不应该一次性读取所有文件，而应该先看目录结构，再有针对性地检索。

### 3. 制定计划

复杂任务需要形成可执行计划，例如先复现问题，再定位错误，再修改代码，最后运行测试。计划应该尽量小步推进，每一步都能验证。
- 第一步：复现问题
- 第二步：查看相关接口
- 第三步：定位失败原因
- 第四步：最小范围修改
- 第五步：运行测试
- 第六步：总结改动

### 4. 调用工具执行

Agent 根据计划调用工具。例如用命令行运行测试，用文件编辑工具修改代码，用搜索工具查找函数被哪些地方引用。每次工具调用后，都要检查输出，而不是盲目继续。

### 5. 观察结果并反思

如果测试通过，Agent 可以继续下一步；如果测试失败，就需要读取错误信息，判断是代码问题、环境问题还是测试数据问题。反思能力决定了 Agent 遇到失败时能否自我修正。

### 6. 完成并汇报

任务结束后，Agent 应该说明做了什么、验证了什么、还有哪些风险。对于代码任务，最好提供测试结果、改动文件和后续建议。
