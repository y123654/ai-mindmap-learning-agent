# AI 智能思维导图系统：具体实施方案 v1.1（稳定优先版）

> 适用项目：在线编写 Markdown，或导入普通文字版 PDF 草稿，由 AI 生成或增量更新思维导图；动画播放期间禁止编辑，完成后支持手动编辑，并根据思维导图生成学科题目。  
> 后端：Java 21 + Spring Boot 3  
> 前端：React + TypeScript + Vite  
> 文档状态：根据可行性复查修订  
> 更新日期：2026-09-11  
> 重要说明：本版本以“能稳定做出来、边界清楚、方便初学者逐步开发”为优先，不追求第一版覆盖所有复杂场景。

> **2026-09-13 交互修订（用户确认后执行）：**
> 1. 左侧 Markdown 编辑器内容过多时必须在编辑器内部滚动；
> 2. 用户在思维导图中手动新增节点后，后端自动把该节点回写到 Markdown，并更新对应文档版本和块快照；
> 3. 节点支持自由拖拽，坐标保存在已有 `mindmaps.graph` JSON 的节点字段中，刷新后保留，可一键恢复自动布局；
> 4. 为避免复杂文档节点过多，思维导图默认只显示一、二、三级标题（图中深度 0–2）；标题以下的列表要点仍生成和保存，但默认折叠，点击标题右上角 `+` 可逐层展开；

> 7. （2026-09-13 稳定性修订）普通段落不再整篇一次性发给 AI：后端按输出 token 体积自动拆成小批次，默认每批最多 6 个段落；各批次返回后由后端统一转换、合并和校验，避免 AI 回复 JSON 被 `max_tokens` 截断导致“Unexpected end-of-input”。

> 16. （2026-09-14 新增登录/注册体系，用户选定方案 1A+2A）
>     - **账号方案（1A 真实后端账号）**：新增 `spring-boot-starter-security` + JJWT 0.12.6；新建 `users` 表（id、username 唯一、password_hash、major、created_at、updated_at）；密码用 BCrypt 加密存储，接口不返回密码；登录成功签发 JWT（HS256，密钥取环境变量 `JWT_SECRET`，内置仅用于本地开发的默认值，有效期 7 天），前端放在 `localStorage` 的 `aimindmap.token`，每个接口请求头带 `Authorization: Bearer <token>`；`JwtAuthenticationFilter` 同时支持 SSE 场景的 `?access_token=` 参数（EventSource 无法自定义请求头）。除 `POST /api/auth/register`、`POST /api/auth/login` 外，`/api/**` 全部需要登录，未登录统一返回 401 JSON（code=UNAUTHORIZED）。注册字段：账号（3-64 字符，唯一）、密码（至少 6 位）、确认密码、专业（1-128 字，必填）。
>     - **数据隔离（2A）**：Flyway V4 迁移新建 users 表，并给 `documents`、`mindmaps`、`questions` 增加可空外键 `user_id`；所有列表/详情/保存/同步/节点/题目接口都在 Controller 边界做归属校验（`OwnershipGuard`，不属于当前用户一律按 404 处理，避免资源存在性泄露）。创建文档/思维导图/题目时写入当前用户 id。
>     - **历史数据归属**：第一个注册成功的账号（注册前 users 表为空）自动接管当前所有 `user_id IS NULL` 的历史 documents/mindmaps/questions；之后注册的新账号只看到空白数据。
>     - **前端**：未登录只能看到登录/注册页（同一页面切换），登录后进入系统；左侧“设置”页显示账号、专业并提供“退出登录”；侧栏底部显示当前账号。前端所有 `/api` 请求走统一 `http()` 封装附加令牌，收到 401 自动清令牌并回到登录页。
>     - **专业字段用途**：`major` 本次只负责保存、回显和随 JWT/`/api/auth/me` 返回；“AI 知识问答智能体 + 按专业生成系统提示词”属于下一批需求，等登录体系验收后另行讨论和设计，本次不实现 AI 问答接口与页面导航。
> 17. （2026-09-14 新增 AI 知识助手，登录体系后的增量功能）
>     - **入口与身份**：左侧导航新增“AI 知识助手”。该入口必须登录后才能访问；后端根据当前登录账号 `users.major` 自动生成系统提示词，前端不能传系统提示词，不能通过请求伪造其他专业身份。
>     - **系统提示词模板**：`你是{领域名称}知识助手。约束：讲解{领域名称}相关理论知识，可按需提供示例、代码片段辅助理解。知识范围：本科{领域名称}相关核心课程。回答规则：1）面向本科学生，语言清晰，分层阐述原理，必要时使用类比；2）解释概念、工作机制、优缺点、适用场景、考点与易混淆知识点；3）代码/示例仅作为原理演示并附文字说明，不提供完整可直接交付的项目成品；4）不确定内容直接说明，禁止编造理论或标准；5）使用 Markdown 结构化排版；6）问题不清楚时主动追问。后续所有对话严格遵守以上规则。`
>     - **第一版边界（稳定优先）**：本次只做“当前页面临时多轮问答”；前端保存本次页面内的上下文并随请求发送，后端不新增聊天会话表、不保存问答记录、不做历史会话列表、不联网检索、不调用笔记/思维导图内容。刷新页面后开始新的临时会话，并提供“清空对话”按钮。
>     - **接口契约**：新增 `POST /api/ai-assistant/chat`；请求体 `{ "messages": [{"role":"user|assistant","content":"..."}] }`，只接受 `user`、`assistant` 两种历史角色，最后一条必须是 `user`；单次最多 20 条消息，单条内容 1-4000 字。响应体 `{ "answer": "Markdown 文本", "provider": "deepseek", "model": "deepseek-chat" }`。系统提示词和专业名由后端从当前用户注入。
>     - **安全与成本**：接口必须携带 JWT；继续复用后端统一 AI 网关、API Key、超时、429/5xx 重试和 Markdown 安全渲染规则；前端不使用 `dangerouslySetInnerHTML`。本功能与思维导图/题目数据隔离，失败时不影响笔记和导图。
> 18. （2026-09-14 AI 知识助手稳定性、历史记录与流式输出修订）
>     - **切换不丢失**：AI 知识助手不再只保存在前端页面内存中；新增 Flyway V5 持久化会话和消息。用户切换左侧导航后再回来，自动恢复上次打开的会话；新会话从第一条用户提问开始保存。
>     - **历史记录**：新增 `ai_chat_sessions`、`ai_chat_messages` 两张表，均带 `user_id` / `session_id` 归属与索引。AI 知识助手页面左侧展示当前用户的历史对话列表，可点击打开；用户只能看到自己的历史。当前版本提供“新对话”和查阅历史，不做删除、重命名、搜索和跨用户分享。
>     - **流式输出**：原一次性 `POST /api/ai-assistant/chat` 临时问答方式被 `POST /api/ai-assistant/sessions/{sessionId}/stream` 取代；后端调用 OpenAI 兼容接口时传 `stream=true`，通过 SSE 形式向前端持续推送 `delta`，完成后推送 `completed` 并一次性保存完整 AI 回复。流式失败不保存半截 AI 回答，已发送的用户问题保留，可重新提问。
>     - **自我介绍口径**：系统内部仍按专业约束回答范围，但用户打招呼或要求自我介绍时，统一说“我是你的知识助手，可以……”，不要说“我是{专业}助手”。前端欢迎语也固定为“我是你的知识助手，可以……”。
>     - **上下文与成本**：后端从数据库读取最近消息作为上下文，最多取最近 30 条，并继续受 `AI_MAX_PROMPT_CHARS` 约束；超过预算时从最旧消息裁剪但保留最后一条用户提问。
> 19. （2026-09-14 AI 知识助手页面布局、完成状态与快捷键修订）

> 20. （2026-09-14 AI 知识助手 SSE 异步转发安全修复）
>     - **问题现象**：AI 流式回答结束时，Tomcat 会对 `StreamingResponseBody` 发起一次 ASYNC 内部转发；自定义 JWT 过滤器默认不处理 ASYNC 转发，导致第二次经过 Spring Security 时没有认证信息，可能记录 `AccessDeniedException: Access Denied`。
>     - **稳定修复**：`JwtAuthenticationFilter` 覆盖 `shouldNotFilterAsyncDispatch()` 并返回 `false`，让初始请求和 SSE 完成时的 ASYNC 内部转发都重新解析同一 JWT；不放宽任何接口权限，不新增匿名访问。
>     - **回归验证**：安全层增加 ASYNC 转发携带有效 JWT 可通过授权的测试；未登录请求仍必须返回 401。
> 21. （2026-09-14 修复 AI 流式回答中途导致前端页面崩溃的 Markdown 渲染死循环）
>     - **问题现象**：向 AI 知识助手提问含二级及以上标题的问题（如“讲解 Dijkstra”）时，AI 流式输出到 ``## ``、``### `` 这类“井号+空格已出现、标题文字尚未到达”的中间帧，前端会瞬间占满内存、标签页崩溃。
>     - **根因**：Markdown 渲染组件中“标题识别正则”要求标题必须有文字（不消费 ``## `` 这种半成品行），而“段落收集的排除正则”只要求井号+空白就把该行排除出段落，导致该行进不了任何分支、行号不前进，外层 `while` 死循环并无限追加空节点。
>     - **稳定修复**：统一标题/围栏/引用/列表的判断正则；标题正则放宽为 ``^(#{1,4})(?:\s+(.*))?$``，半成品标题行也被消费为空标题（下一帧补全）；段落收集改为 do/while 保证至少消费当前行；外层循环增加“本轮若行号未推进则强制 +1”的防御性兜底，任何分支都不允许不前进。
>     - **回归验证**：用“完整回答 + 逐字符流式中间帧”方式验证 800+ 次渲染，包含 ``#``、``## ``、``### ``、未闭合围栏、未闭合行内代码、孤立星号、表格、代码块等边界，均不再崩溃。
> 22. （2026-09-16 AI 知识助手回答支持 Markdown 表格渲染）
>     - **需求**：AI 回答中的 GFM 表格（``| 列 | 列 |`` + ``|---|---|`` 分隔行）此前按普通段落文本显示，现渲染为带表头、边框、斑马纹的正式表格；窄屏时表格外层可横向滚动，不挤压消息气泡布局。
>     - **流式安全要求**：流式中间帧只有表头行、分隔行未到达时先按普通文本显示，分隔行到达后立即转为表格；分隔行/数据行只到达一半时也必须能安全渲染，不允许重蹈修订第 21 条的死循环。表格单元格内容继续走纯文本 inline 渲染（行内代码、加粗），不使用 HTML 注入。
>     - **兼容规则**：支持分隔行中的对齐标记（``:---`` 左对齐、``:---:`` 居中、``---:`` 右对齐）；列数以表头为准，缺失单元格补空、多余单元格截断。

## 0. v1.1 相比 v1.0 的主要变化

| 调整项 | v1.0 做法 | v1.1 稳定版做法 | 调整原因 |
|---|---|---|---|

| 第一版同步方向 | Markdown → 思维导图 | **2026-09-13 修订：Markdown 主导，手动新增节点可自动回写 Markdown；AI 节点不反向覆盖原文** | 满足手动图节点需要落回文档，同时避免 AI 内容重写用户原文 |
| 第一版主要变化 | 新增标题、新增列表项、修改普通段落、追加知识 | 不优先处理整章移动、重复节点合并 |
| 标题和列表 | 程序规则直接生成节点 | 不调用 AI，结果更可控 |
| 普通段落 | AI 压缩、归纳并生成节点 | AI 只提供建议；每个段落最多一个短节点，后端忽略 AI 自建父子关系并强制平铺到所属标题，标题式标签自动改成段落摘录；同步时自动按每批最多 6 个段落小批量请求并合并结果；案例只保留结论，风险/约束必须保留，不直接复制长段原文 |
| 手动新增节点 | 默认永久保留，保存后自动回写到 Markdown | AI 不能修改或删除；回写后仍标记为 manual/manualLocked |
| 手动改过的节点 | 默认保护 | AI 不覆盖标题；可在后续版本提供“允许 AI 重写”开关 |
| Markdown 删除内容 | 只提示删除建议 | 用户确认后才真正删除 |
| 生成动画 | 后端先生成完整目标图，前端再播放 | 不做 AI 边返回、节点边出现的不可控动画 |
| 动画期间编辑 | 前端锁定，后端也校验状态和版本 | 防止刷新、重复提交或异常请求破坏数据 |
| 题目生成 | 根据用户编辑后的最新思维导图 | 题目是 AI 初稿，需要用户确认 |
| PDF | 后续阶段支持普通文字版 PDF 转 Markdown 草稿 | 不支持扫描件、公式、复杂表格和复杂双栏版面 |
| 智能体形式 | 固定 AI 工作流 | 不是第一版就做自主 Agent |

### 3.3 AI 接口

第一版接入 **OpenAI 兼容 Chat Completions 接口**，默认推荐 DeepSeek：

```bash
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=你的密钥
AI_MODEL=deepseek-chat
AI_TIMEOUT_SECONDS=60
AI_MAX_RETRIES=1
# 可选：默认 2000；后端会按该值自动拆分 AI 小批次
AI_MAX_OUTPUT_TOKENS=2000
# 可选：单次 AI 请求提示词最大字符数，默认 12000
AI_MAX_PROMPT_CHARS=12000
```

要求：

1. API Key 只保存在后端；
2. 前端打包文件中不能出现密钥；
3. 日志不能打印完整密钥；
4. 后端封装 `AiGateway`，以后可切换 OpenAI、通义千问、智谱、Ollama；
5. 优先开启服务商支持的 JSON 输出模式；
6. AI 超时、JSON 截断/解析失败、校验失败时，先按 `AI_MAX_RETRIES` 对当前小批次重试；最终仍失败时不覆盖旧思维导图；
7. 普通段落默认按小批次请求（每批最多 6 个），避免新建长文档时一次性生成过大的 JSON。

### 4.1 为什么第一版是固定工作流，不是真正 Agent

第一版系统按固定步骤执行：

1. 保存 Markdown；
2. 解析 Markdown；
3. 比较稳定块；
4. 规则生成标题和列表操作；
5. 必要时调用 AI；
6. 校验操作；
7. 生成目标图；
8. 播放动画；
9. 发布新图；
0. 根据最新图生成题目。

这样做的优点是每一步都能测试，失败时知道问题在哪里。等核心流程稳定后，再把某些步骤替换成工具调用型 Agent。

## 5. 核心用户流程

### 5.1 保存 Markdown

```text
用户编辑 Markdown
      │
      ▼
点击保存
      │
      ▼
前端提交 content 和 expectedVersion
      │
      ▼
后端检查版本
      │
      ├─ 版本一致：保存并返回新版本
      │
      └─ 版本不一致：返回冲突，提示刷新或另存
```

```text
用户点击“同步到思维导图”
      │
      ▼
前端立即锁定 Markdown 和画布
      │
      ▼
后端创建同步任务
      │
      ▼
解析 Markdown 为稳定内容块
      │
      ▼
比较旧版本和新版本
      │
      ├─ 标题/列表变化：程序生成规则操作
      │
      └─ 段落/复杂关系：调用 AI 生成建议
      │
      ▼
合并操作并校验
      │
      ▼
生成正式节点 ID 和目标思维导图
      │
      ▼
任务状态变为 READY
      │
      ▼
前端按层级播放动画
      │
      ▼
动画完成后调用 complete
      │
      ▼
后端发布目标图并解锁
```

### 5.3 同步失败

```text
AI 超时 / JSON 错误 / 校验失败
      │
      ▼
同步任务标记 FAILED
      │
      ▼
当前已发布思维导图不变
      │
      ▼
前端显示失败原因和“重试”按钮
      │
      ▼
用户停留在旧 Markdown 和旧思维导图状态
```

### 5.4 动画期间刷新页面

```text
页面重新打开
      │
      ▼
查询文档和同步任务
      │
      ├─ FAILED：显示失败，可重试
      ├─ READY：继续播放或跳过动画
      ├─ ANIMATING：提供继续播放或跳过动画
      └─ COMPLETED：显示最新思维导图
```

任务超过一定时间仍停留在 `ANIMATING`，例如 10 分钟，后端可允许用户跳过动画并发布已经生成好的目标图。

### 5.5 手动编辑思维导图

第一版允许：

- 新增子节点；
- 修改节点标题；
- 修改节点摘要；
- 删除用户确认删除的节点；
- 接受或拒绝“建议删除”。

第一版不保存：

- 自由拖拽后的节点坐标；
- 节点之间的额外连线。

React Flow 可以保留浏览时缩放和平移，但不建议开放自由位置保存，避免布局和树结构冲突。

## 7. 稳定的数据结构

### 7.1 思维导图节点

v1.1 仍使用树形结构，但比 v1.0 增加版本和保护所需字段：

```json
{
  "id": "node_001",
  "label": "光合作用",
  "summary": "绿色植物利用光能合成有机物并释放氧气的过程",
  "sourceType": "markdown",
  "sourceBlockId": "blk_stable_001",
  "sourceAnchor": "光合作用#heading:1",
  "sourcePath": ["光合作用"],
  "manuallyEdited": false,
  "manualLocked": false,
  "status": "active",
  "layout": null,
  "createdAt": "2026-09-11T10:00:00Z",
  "updatedAt": "2026-09-11T10:00:00Z",
  "children": []
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 后端生成的正式节点 ID |
| `label` | 节点短标题 |
| `summary` | 节点解释，可为空 |
| `sourceType` | `markdown`、`manual`、`ai_enhanced` |
| `sourceBlockId` | Markdown 稳定块 ID，可为空 |
| `sourceAnchor` | 标题路径、块类型和顺序组成的稳定锚点 |
| `sourcePath` | Markdown 标题路径 |
| `manuallyEdited` | 用户是否改过标题或摘要 |
| `manualLocked` | 是否完全禁止 AI 操作 |
| `status` | `active` 或 `removed_suggested` |
| `layout` | **2026-09-13 新增**：节点自由坐标，未手动拖拽时为 `null`；结构为 `{x,y,manuallyPositioned}` |
| `children` | 子节点 |

### 7.2 节点自由坐标（2026-09-13 修订）

用户已确认第一版需要自由拖拽，因此节点允许保存坐标。该坐标属于显示层信息，保存在已有 `mindmaps.graph` JSON 中，不新增数据库表、不新增 Flyway 迁移。

```json
"layout": {
  "x": 120,
  "y": 80,
  "manuallyPositioned": true
}
```

规则：

1. 自动布局生成的节点 `layout=null`，由 ELK 计算临时坐标；
2. 用户拖拽结束后，前端调用坐标保存接口，后端写入 `layout.x/layout.y/layout.manuallyPositioned=true`；
3. 拖拽只改变显示位置，不改变父子层级，不产生 `move_node`；
4. 后续同步保留已有节点坐标；新节点仍使用自动布局；
5. 用户点击“恢复自动布局”后清空全图节点的 `layout`，重新交给 ELK 排版；
6. 拖拽保存属于显示层更新，不递增语义图版本 `graphVersion`，但更新 `graph` JSON 和 `updatedAt`。

### 7.3 图对象

```json
{
  "rootId": "node_001",
  "version": 3,
  "nodes": [
    {
      "id": "node_001",
      "label": "光合作用",
      "children": []
    }
  ],
  "updatedAt": "2026-09-11T10:00:00Z"
}
```

为了前端使用方便，后端可以同时返回：

- `tree`：嵌套 children 结构；
- `flatNodes`：扁平节点列表；
- `version`：图版本。

数据库中建议保存完整 `tree` JSON，也可额外保存扁平化节点表用于查询。第一版数据量不大时，先保存 JSON 即可。

## 8. Markdown 稳定块设计

### 8.1 MarkdownBlock

```java
public record MarkdownBlock(
        String blockId,
        BlockType type,
        String text,
        String normalizedText,
        List<String> headingPath,
        Integer level,
        Integer order,
        String anchor,
        String contentHash
) {
}
```

### 8.2 块类型

```java
public enum BlockType {
    HEADING,
    PARAGRAPH,
    BULLET_LIST_ITEM,
    ORDERED_LIST_ITEM,
    QUOTE,
    CODE_BLOCK,
    TABLE,
    OTHER
}
```

### 8.3 稳定锚点

不要只使用 `blk_1`、`blk_2` 这种顺序编号。建议根据内容生成稳定锚点：

```text
HEADING:  光合作用 > 原料#heading(2)
LIST:     光合作用 > 原料#bullet(二氧化碳)
PARAGRAPH: 光合作用#paragraph(order=5)
```

稳定锚点不一定保证所有复杂编辑都 100% 对齐，但比纯顺序编号稳定得多。

### 8.4 规范化规则

计算哈希前先做规范化：

1. 统一换行符；
2. 去掉行尾多余空格；
3. 连续空行压缩；
4. 中文标点和英文标点按需要保留，不随意改变含义；
5. 列表前导符号不参与文本内容；
6. Markdown 粗体、斜体标记可在纯文本中移除；
7. 保留代码块原文，代码块第一版不生成知识节点。

建议哈希：

```text
SHA-256(normalizedText + "|" + type + "|" + headingPath)
```

### 8.5 差异比较策略

比较顺序：

1. 优先用 `anchor` 匹配；
2. 再用“标题路径 + 块类型 + 内容哈希”匹配；
3. 新增列表项可结合相邻节点判断插入位置；
4. 文本小修改可使用相似度比较；
5. 无法确定是修改还是删除新增时，按“新增 + 建议删除旧节点”处理，避免错误覆盖。

输出：

```json
{
  "added": [],
  "changed": [],
  "removed": [],
  "unchanged": [],
  "uncertain": []
}
```

`uncertain` 表示程序无法确定的变化，可以交给 AI 或提示用户确认。

> **【v1.1 修订记录 · 2026-09-12 · 方案 A：标题改名“搬家识别”】**
>
> **难点**：稳定锚点包含上级标题文字（如 `光合作用 > 原料#bullet(二氧化碳)`），把 `## 原料` 改名为 `## 原材料` 时，标题自身锚点不含自身文字（`光合作用#heading(2)`），可经第 1 步锚点+哈希识别为改名；但子标题、列表项的锚点前缀随上级标题整体改变，原文第 4 条相似度配对要求“标题路径完全相同”，导致这些子节点被误判为新增，造成节点重复。
>
> **修订内容（只改差异比较与操作生成内部逻辑，不改数据库表结构、DTO、接口契约和 §8.5 输出的五个 JSON 键）**：
>
> 1. **识别迁移关系**：从第 1 步已配对的改名标题（同锚点、不同哈希）以及剩余标题中，按标题级别由浅到深、父路径应用已有迁移后相同、同级别做相似度贪心配对，记录“旧标题全路径 → 新标题全路径”的路径迁移关系。多级标题同时改名时，按“最长旧前缀命中一次”的规则级联应用。
>
> 2. **子块平移再匹配**：把尚未配对的旧块的 `headingPath` 和锚点路径前缀按迁移关系平移（`blockId` 是旧锚点哈希，保持不变），再做第二轮锚点匹配：文字相同的归为内部类别 `relocated`（搬家），文字也变了归为 `changed`。嵌套列表父项改名的场景，由第 4 条相似度配对中文字完全相同的配对补充覆盖，同样归为 `relocated`。
> 3. **静默更新**：搬家块生成 `update_node` 操作，但只刷新图节点的内部溯源字段（`sourceBlockId`、`sourceAnchor`、`sourcePath`），**不改变节点文字**，因此前端不做“改名琥珀色高亮”，视觉上只有被改名的标题 1 个节点变色；手动保护规则（`manual` / `manuallyEdited` / `manualLocked`）对搬家同样有效，用户动手改过的节点不迁移。
> 4. **变更摘要**：`relocated` 块计入 `unchanged` 数量（文字本就没变），不新增 JSON 键；涉及类为内部记录类 `MarkdownDiff.relocated`，不对外增加字段。
> 5. **后续兼容性**：基线快照始终以新版块 ID 写入；若搬家时节点处于手动保护状态而跳过元数据刷新，只意味着该手动节点保留旧锚点，下次同步仍可经第 4 条相似度找回，不影响其他节点和后续阶段 3/4 的设计。

### 8.6 根节点规则

- Markdown 有且只有一个一级标题：一级标题作为根节点；
- 没有一级标题：使用文档标题作为根节点；
- 有多个一级标题：使用文档标题作为总根节点，每个一级标题作为子节点。

## 9. 增量操作格式

### 9.1 AI 临时操作格式

AI 返回的 ID 使用 `tmp_` 前缀，不能直接进入正式图。2026-09-13 三次修订后，普通段落新增节点必须满足“一段一个、平铺挂载”：

```json
{
  "operations": [
    {
      "type": "add_node",
      "clientTempId": "tmp_001",
      "parentClientTempId": null,
      "parentNodeId": null,
      "afterNodeId": null,
      "node": {
        "label": "影响光合作用速率",
        "summary": "根据当前段落归纳出的单个具体要点",
        "sourceType": "ai_enhanced",
        "sourcePath": [],
        "sourceBlockId": "blk_xxx"
      },
      "reason": "普通段落归纳；父节点由后端按 sourceBlockId 所属标题决定"
    }
  ]
}
```

后端忽略 AI 返回的 `parentClientTempId`、`parentNodeId` 和 `afterNodeId`，禁止 AI 生成目录式父节点。若同一个 `sourceBlockId` 返回多个节点，只保留 AI 树中较深、较具体的一个；若标签与 Markdown 标题相同或带章节编号，后端自动改为该段落开头摘录。

### 9.4 冲突保护规则

1. `sourceType = manual` 的节点，AI 永远不能修改或删除；
2. `manualLocked = true` 的节点，AI 永远不能修改或删除；
3. `manuallyEdited = true` 的节点，AI 不能覆盖 `label`；
4. 是否允许 AI 更新 `summary`，第一版也默认禁止，后续可增加设置；
5. AI 新增节点不能直接指定正式 ID；
6. 父节点不存在时操作失败；
7. 根节点不允许删除；
8. 单次新增节点默认最多 100 个，硬上限可配置为 200；
9. 操作层级最多 6 层；
10. 标题建议不超过 20 个中文字符；
11. 摘要建议不超过 60 个中文字符；
12. 校验任一操作失败，本次同步整体失败，不发布半成品；
13. **2026-09-13 三次修订：普通段落 AI 新增节点必须携带本次真实 `sourceBlockId`；一个段落最多保留一个节点；**
14. **AI 新增节点只能平铺在该段落所属 Markdown 标题节点下，不能挂到另一个 AI 节点下；`parentClientTempId` 仅用于 AI 内部表达，后端转换时忽略；**
15. **AI 节点标签不能复制 Markdown 标题或章节编号；违反时后端用该段落开头摘录作为标签；**
16. **AI 返回分组壳、目录树或重复结构时，后端只保留具体段落要点并拍平，避免“套娃”。**
17. **（2026-09-17 新增，大导图三级裁剪）预计单次新增节点超过 100 个时，后端 `MindMapDepthCap` 在规则构建后、AI 调用前做结构裁剪：只保留 H1–H3 标题、一级缩进无序列表项；深层段落不送 AI；合并后再按图中深度 ≤ 3 兜底过滤。裁剪后按硬上限 `MAX_NEW_NODES_HARD = 200` 校验（常规同步上限仍为 100）。裁剪触发、保留/丢弃数量、超限失败必须在后端日志可见（WARN/INFO）。深层 Markdown 内容与块快照不受影响。**

#### 历史会话接口

- `GET /api/ai-assistant/sessions`：获取当前用户的历史会话列表，按最近更新时间倒序。
- `POST /api/ai-assistant/sessions`：创建空会话，默认标题“新对话”。
- `GET /api/ai-assistant/sessions/{sessionId}`：获取某个会话详情和消息列表；不属于当前用户返回 404。
- `DELETE /api/ai-assistant/sessions/{sessionId}`（修订第 23 条）：删除某个会话及其全部消息（消息级联物理删除）；不属于当前用户返回 404，成功返回 204；流式回答进行中前端不允许点击删除。

#### `POST /api/ai-assistant/sessions/{sessionId}/stream`

请求：

```json
{ "content": "你好" }
```

响应：`text/event-stream`，事件包括：

```text
event: delta
data: {"content":"你"}

event: completed
data: {"message":{"id":1,"role":"assistant","content":"..."},"session":{"id":1,"title":"你好"}}

event: error
data: {"code":"AI_STREAM_FAILED","message":"AI 流式回答失败，请稍后重试"}
```

规则：

- 接口必须登录，会话必须属于当前用户；
- 请求内容去除首尾空格后长度为 1-4000 字；
- 第一条用户消息自动生成会话标题（取内容开头，最长 40 字）；
- 用户消息先保存，AI 完整回答成功后才保存 assistant 消息；
- AI 流式失败时不保存半截回答；
- 后端从数据库读取最近 30 条消息，并按 `AI_MAX_PROMPT_CHARS` 预算裁剪旧上下文；
- 前端用带 JWT 的 Fetch + ReadableStream 读取 SSE；历史记录从数据库恢复。
- 前端页面占满登录后主工作区的可用高度；历史对话列表和聊天消息列表分别在自己的区域内滚动，输入区始终固定在聊天面板底部；
- 前端以 `completed` 事件作为一次问答完成的结束信号，收到后立即结束“回答中”状态，不再依赖底层 HTTP 流关闭时间；
- 输入框支持 Enter 发送、Shift+Enter 换行；中文输入法组词期间按 Enter 不发送，避免把选择候选词误判为提交。
- SSE 接口的初始请求和完成时 ASYNC 内部转发都必须能解析同一 JWT；`JwtAuthenticationFilter` 需要处理 ASYNC 转发，避免流式回答结束时抛 AccessDeniedException，且不得把该接口放宽为匿名访问。
- 前端 Markdown 渲染器必须保证：任意流式中间帧（例如只有 `## `、`### `、未闭合代码围栏、未闭合行内代码）都能被正常消费，不允许出现“某一行不被任何分支处理导致行号不前进”的死循环；主循环必须有行号未推进时强制前进的兜底。

`POST /api/ai-assistant/chat` 是修订第 17 条中的一次性临时问答接口：消息只从前端请求传入，不保存历史。该接口已被修订第 18 条的 `/sessions/{sessionId}/stream` 取代；当前代码不得继续调用或新增该接口，历史会话一律以数据库中的 `ai_chat_sessions` 和 `ai_chat_messages` 为准。

## 12. AI 提示词和返回校验

### 12.1 思维导图增量提示词

```text
你是一个学科知识结构化助手。

任务：
根据“新增或修改的 Markdown 内容块”和“当前思维导图”，生成增量操作建议。

硬性规则：
1. 只能返回 JSON，不允许返回 Markdown 代码块。
2. 只允许 add_node、update_node、noop；不允许删除节点，删除 Markdown 内容由后端规则生成删除建议。
3. 不允许修改 manual 节点，不允许覆盖 manuallyEdited=true 或 manualLocked=true 的节点。
4. 新增节点的临时 ID 使用 tmp_ 前缀，不能伪造正式 node id。
5. 每个 changedBlocks 输入块最多返回一个 add_node，node.sourceBlockId 必须原样填写该块 blockId。
6. 新增普通段落节点时 parentClientTempId、parentNodeId、afterNodeId 都返回 null；禁止生成 AI 子树、分组节点、目录节点。
7. 新增节点标题必须概括当前段落的具体知识点，禁止照抄或改写 Markdown 标题，禁止生成“一、什么是 Agent”“1. 大语言模型”等章节名。
8. 每个节点标题不超过 20 个中文字符，summary 不超过 60 个中文字符，不能编造段落中没有的事实。
9. update_node 只能更新 currentMindmap 中 sourceBlockId 出现在 fromBlockId 里的既有 AI 节点。
10. 即使违反第 5–7 条，后端也会丢弃分组壳、忽略 AI 父节点并强制平铺；AI 应尽量一次返回符合规则的结果。
11. 后端会把普通段落拆成小批次请求，默认每批最多 6 个；AI 每次只能为本次 `changedBlocks` 中实际列出的块返回操作，多批结果由后端合并后统一校验。
12. 信息降噪：普通段落只保留核心名词、关键结论、重要限制，删除铺垫、过渡语、重复解释；禁止整段复制，案例/故事只提炼背后的结论，没有明确结论时返回 noop。
13. 同段重复语义合并；风险、警告、约束、前提条件必须保留；“备注/补充说明/注意事项”仍归入原章节，不新增独立主分支。
14. 严格遵守输入块 `headingPath`，不能跨章节挂载；AI 不得通过父节点字段改变归属，正式父节点仍由后端按 Markdown 路径决定。
15. 输出前必须做三轮自检：①本批有效块不漏；②父相关字段全部为 null；③未编造知识、未粘贴长段、未输出 Mermaid/XMind/图片/解释文字。

> 2026-09-13 方案 A 说明：用户提供的“输出 Mermaid mindmap 代码块”提示词不直接采用。当前系统仍以 JSON 增量操作为唯一 AI 契约，Mermaid 可作为后续独立预览/导出功能，不能替代可编辑画布的内部数据。
```

### 12.2 JSON 处理步骤

后端按以下顺序处理 AI 输出：

1. 如果服务商支持 `response_format=json_object`，优先开启；
2. 接收原始字符串；
3. 使用 Jackson 解析；
4. 如果失败，尝试去掉首尾空白和 Markdown 代码块；
5. 再次解析；
6. 按 Java DTO 做字段类型校验；
7. 执行业务规则校验：一段一个节点、忽略 AI 父节点、按真实标题路径平铺、标题式标签改写；
8. 通过后生成正式节点 ID 和目标图；
9. 任一环节失败则任务失败。

### 13.2 同步引擎

```java
@Service
public class SyncEngine {

    private final MarkdownParser markdownParser;
    private final MarkdownBlockDiffer blockDiffer;
    private final RuleOperationBuilder ruleOperationBuilder;
    private final MindMapPromptService promptService;
    private final AiGateway aiGateway;
    private final MindMapOperationValidator operationValidator;
    private final GraphPreviewBuilder graphPreviewBuilder;
    private final NodeIdGenerator nodeIdGenerator;

    public SyncPreview prepare(SyncContext context) {
        var oldBlocks = markdownParser.parse(context.oldMarkdown());
        var newBlocks = markdownParser.parse(context.newMarkdown());

        var diff = blockDiffer.diff(oldBlocks, newBlocks);

        var ruleOperations = ruleOperationBuilder.build(
                diff,
                context.currentGraph()
        );

        var aiOperations = aiRequired(diff)
                // 稳定性处理：普通段落自动拆成小批次请求，避免单次 AI JSON 被 max_tokens 截断。
                ? askAiForOperationsInSmallBatches(context.currentGraph(), diff, ruleOperations)
                : List.<ValidatedOperation>of();

        var mergedOperations = OperationMerger.merge(ruleOperations, aiOperations);

        operationValidator.validate(mergedOperations, context.currentGraph());

        var targetGraph = graphPreviewBuilder.preview(
                context.currentGraph(),
                mergedOperations,
                nodeIdGenerator
        );

        return new SyncPreview(mergedOperations, targetGraph);
    }

    private boolean aiRequired(MarkdownDiff diff) {
        return !diff.addedParagraphs().isEmpty()
                || !diff.changedParagraphs().isEmpty()
                || !diff.uncertain().isEmpty();
    }
}
```

小批次实现要求：

- `MindMapPromptService` 根据 `AI_MAX_OUTPUT_TOKENS` 估算每批段落数，默认上限为 6；
- 每个批次仍携带同一份规则操作和当前图精简结构，但只发送本批次的新增/修改/不确定普通段落；
- 后端顺序调用 AI，累计 token 与耗时，所有批次返回后统一执行转换、合并和校验；
- 任一批次最终失败，本次同步整体失败，旧思维导图保持不变。

### 13.3 事务原则

- AI 调用不要放在数据库长事务中；
- 同步过程先更新任务状态；
- AI 返回并校验通过后，把 `targetGraph` 保存到任务；
- 用户动画完成调用 `complete` 时，才在一个短事务中发布目标图；
- 发布时再次检查图版本；
- 发布失败不删除旧图。

### 13.4 后端锁规则

同一文档只允许一个活动同步任务。活动状态包括：

```text
PENDING、PARSING、DIFFING、AI_GENERATING、VALIDATING、READY、ANIMATING
```

如果用户重复点击：

- 已有活动任务时，不创建新任务；
- 前端直接显示当前任务进度；
- 旧任务超时后由后端标记失败或允许取消。

11. 后端发布成功后解锁。


### 14.5.6 默认折叠状态（2026-09-17 修订第 33 条）

思维导图初始展示必须默认折叠，避免大导图生成后一次性铺满画布：

| 场景 | 行为 |
|---|---|
| 新建空导图后首次同步 | 动画播放时展示可见节点的逐层生成，动画结束后只显示中心主题 |
| 打开已有导图 | 默认只显示中心主题，根节点显示 `+`，点击后展开第一层 |
| 用户逐层展开 | 每个有可见子节点的节点显示 `+/-`；展开父节点时，其子节点默认仍保持折叠，除非用户继续展开 |
| 用户手动新增节点 | 自动展开新增节点的父节点，避免新增后被折叠隐藏 |
| 节点总数 > 100 的紧凑模式 | 仍只允许显示深度 0–3；根节点、第一层、第二层可展开/折叠，第三级不显示继续展开或新增子节点按钮 |
| 数据与后端 | 折叠只影响前端渲染和 ELK 布局输入，不删除节点、不改变后端 `graph` JSON、不影响出题和同步 |

默认折叠集合由前端根据完整树中有子节点的节点 ID 计算；同步动画结束后重新计算一次折叠集合，再调用 `onAnimationDone` 解除动画锁。

### 14.6 阶段 4 题目面板

- 顶部“生成题目”按钮展开/收起底部题目面板；
- 面板可填写学科、年级、难度、数量，可勾选单选题和简答题；
- 第一版默认根据整份最新思维导图出题，后端支持 `nodeIds` 精确指定知识点，前端后续可增加节点多选；

### 14.5 节点折叠、展开和自由拖拽（2026-09-13 修订）

#### 14.5.1 默认显示深度

为防止复杂文档首屏节点过多，前端默认只展开到图中深度 2（一、二、三级标题）：

| 图中深度 | 典型内容 | 默认行为 |
|---|---|---|
| 0 | 一级标题 `#`，根节点 | 显示 |
| 1 | 二级标题 `##` | 显示 |
| 2 | 三级标题 `###`；没有三级标题时，二级标题下直接挂的列表项也在这一层 | 节点本身显示；若它还有子节点，则子节点默认折叠 |
| 3 及更深 | “感知、思考、行动、记忆”等列表要点，以及“接收用户输入”等嵌套列表 | 默认折叠隐藏，逐层点开 |

规则统一表述：**深度 ≥ 2 且含有子节点的节点默认折叠**。因此：

- 类似 `# → ## → ### → - 感知` 的长文档，首屏只显示到“1. Agent 的基本能力”这类三级标题，“感知/思考/行动/记忆”等要点默认隐藏；
- 类似 `# 光合作用 → ## 原料 → - 二氧化碳` 的短文档，列表项本身在深度 2 且没有子节点，仍会直接显示。

深层节点仍然由后端解析、保存和参与同步，只是在前端默认隐藏。每个子节点被隐藏的节点显示 `+` 展开按钮，点击后只展开下一层；再点可折叠。折叠状态是前端显示状态，第一版不写入数据库。用户点击某个节点的“新增子节点”时，前端自动展开该节点，保证新增节点立即可见。

#### 14.5.2 自由拖拽

- 普通状态：节点可拖拽；
- 同步、READY、动画期间：节点不可拖拽；
- 拖拽不改变父子关系，只改变 `layout.x/y`；
- 已手动定位的节点刷新后仍在原位置；
- 新增节点没有 `layout`，继续由 ELK 自动布局；
- “恢复自动布局”清空所有 `layout` 后重新排版。

#### 14.5.3 手动节点回写后的编辑器状态

节点新增成功后，前端使用响应中的 `documentContent/documentVersion` 更新左侧编辑器内容和版本号，避免用户再点保存 Markdown 时发生版本冲突。回写内容来自后端，前端不直接拼接 Markdown。
#### 14.5.4 大导图紧凑模式（2026-09-17 新增）

当完整导图节点总数（裁剪前，含各层级全部节点）**超过 100 个**时，前端自动进入紧凑模式，防止大文档（例如 248 个节点的 Agent 知识 PDF）首屏节点过密。

**后端侧（2026-09-17 修订第 30 条，用户选择“偏向 C”）**：大文档在同步生成阶段就只生成“前三级”——H1–H3 标题、一级缩进列表项、挂载深度 ≤ 3 的段落 AI 节点；二级及更深嵌套列表不生成节点（Markdown 原文与块快照仍保留）。这类导图入库时节点本身就只有前三级（Agent PDF 实测：预测 251 个，保留 89 个标题/列表节点加约 40 个段落节点，丢弃 122 个深层嵌套列表节点）。前端紧凑模式继续作为显示层兜底（例如后续手动编辑使节点数再次超过 100 时）。

> 修订第 31 条补充：上述“一级/二级列表”以 Markdown 草稿中真实缩进为准。PDF 导入必须先按横向 x 坐标还原列表缩进；对同一份 Agent PDF，修复后识别为标题 32 个、一级列表 58 个、二级列表 122 个、段落 40 个，裁剪后保留 90 个标题/一级列表节点，预计最终约 130 个节点。修复前已接受的旧草稿若已被拍平，不自动变化，需要重新导入或经用户确认后修复数据。

前端紧凑模式规则如下：

| 规则 | 说明 |
|---|---|
| 触发条件 | 完整树节点总数 > 100；≤ 100 时维持 §14.5.1 原折叠逻辑 |
| 显示深度 | 只渲染图中深度 0（中心主题）、1（一级分支）、2（二级）、3（三级要点），深度 4 及更深不参与渲染和 ELK 布局 |
| 数据保留 | 深层节点仍完整保存在 `mindmaps.graph` 中，后端解析、同步、题目生成、版本与保护锁逻辑完全不变；只是前端不显示 |
| 第三级节点按钮 | 不显示折叠/展开“+/−”按钮（没有更深内容可展开）；不显示“新增子节点 ＋”按钮（避免新增第四级后用户看不到）；“改名 ✎”“删除 🗑”按钮保留 |
| 第二级节点 | 同步动画播放期间临时展开；动画结束后按修订第 33 条恢复默认折叠，用户可手动展开第三级 |
| 动画 | AI 同步生成动画同样只播放深度 0–3 的节点，深层节点不参与逐层显现；动画结束后导图默认只显示中心主题 |
| 阈值口径 | 按裁剪前完整节点数判断；阈值常量 `COMPACT_NODE_THRESHOLD = 100`、最大显示深度 `COMPACT_MAX_DEPTH = 3` 定义在 `MindMapCanvas.tsx` |
| 提示文案 | 工具栏显示“节点较多（共 N 个），为避免拥挤只显示前三级，更深的要点已自动收起” |

本规则只改前端显示与按钮可见性，不新增数据库表、不改接口契约和 JSON 结构；手动新增节点仍只允许挂到深度 0–2 的节点上（紧凑模式下），新增后照常回写 Markdown。

### 14.5.5 节点紧凑显示与间距（2026-09-17 修订第 32 条）

### 14.10 导出功能（阶段 6A，修订第 34 条）

- **Markdown 导出**：纯前端 Blob 下载（`text/markdown;charset=utf-8`），导出当前编辑器内容而非强制读服务器版本，未保存的修改也会被导出；文件名由笔记标题经 `sanitizeFileName` 清洗得到。

- **导出范围**：PNG 导出完整导图（所有层级），不受第 29 条紧凑模式显示深度和第 33 条默认折叠影响；这两个规则只影响平时屏幕展示，不影响导出内容。
- **禁用时机**：同步任务锁定中、动画播放中、无导图时禁用导出 PNG；导出过程中再次点击无效（按钮显示“导出中...”）。
- **不做的事**：不导出 SVG/PDF、不做服务端渲染、不记录导出历史、不新增接口和表；`html-to-image` 仅在浏览器端运行。

## 15. PDF 方案（后续阶段）

### 15.1 支持范围

第四阶段只支持：

- PDF 中的文字可以复制；
- 单栏或版面较简单；
- 没有大量公式；
- 没有复杂跨页表格；
- 文件大小建议不超过 20MB；
- 页数建议先限制在 100 页以内。

### 15.2 处理流程

```text
上传 PDF
   │
   ▼
检查文件类型和大小
   │
   ▼
PDFBox 提取文字
   │
   ├─ 文字过少：判定疑似扫描件，停止并提示
   │
   └─ 文字可用：清理页眉页脚和断行
              │
              ▼
        根据字号猜测标题，根据横向 x 坐标还原列表缩进
              │
              ▼
        生成保留层级的 Markdown 草稿
              │
              ▼
        用户人工检查
              │
              ▼
        点击同步思维导图
```

### 15.3 扫描件判断

满足任一条件时标记疑似扫描件：

- 平均每页可提取文字少于设定阈值；
- 大量页面提取文本为空；
- 文本长度与页数明显不匹配；
- 页面主要内容是图片。

提示文案：

```text
这个 PDF 可能是扫描件或图片版资料，当前版本无法准确识别文字。
后续版本可以接入 OCR 文字识别。
```

### 15.4 PDF 实现注意事项

正式代码不要只用 `file.getBytes()` 读取大 PDF。建议：

- 使用临时文件；
- 使用 try-with-resources 关闭 `PDDocument`；
- 限制文件大小和页数；
- 设置解析超时；
- 保存系统生成的文件名；
- 上传目录不可执行；
- 不信任原始文件后缀，检查文件头；
- 文本行必须记录横向起点 x，项目符号按全文横坐标档位还原 Markdown 列表缩进；不能在草稿规范化时 `trim()` 掉列表前导空格；
- 修复前已经接受的“列表拍平”旧草稿不自动追溯修改，需重新导入或经用户确认后做一次性数据修复。

## 16. 安全和成本控制

### 16.1 API Key

- 只保存在后端环境变量或服务器安全配置中；
- 不放在前端；
- 不写进 Git 提交；
- 日志脱敏；
- 公网部署必须先加登录认证。

### 16.2 文件上传

- 限制扩展名和 MIME 类型；
- 检查文件头；
- 限制大小；
- 使用系统生成文件名；
- 文件不保存到可执行目录；
- 后续加病毒扫描或对象存储策略。

### 16.3 AI 输出

AI 输出不能直接保存或执行：

- JSON 必须解析成功；
- DTO 类型必须正确；
- 节点数量必须受限；
- 父节点必须存在；
- 手动节点必须受保护；
- 题目答案必须有效；
- 文本内容由 React 默认转义显示；
- 不使用 `dangerouslySetInnerHTML`。

### 16.4 成本控制

- 只有规则无法处理的段落才调用 AI；
- 未变化的块不发送给 AI；
- 单次请求限制最大字符数；
- 普通段落自动小批次请求（默认每批最多 6 个），避免 AI 输出 JSON 被截断；
- 更大的长文档按章节拆分/续生成作为后续增强；
- 第一版按钮触发，不做实时同步；
- 记录模型、耗时、Token、失败原因；
- 题目生成单次最多 10 道，题目 AI 输出 token 上限按 6000 控制，避免长 JSON 被截断；
- 设置每用户或全局调用上限；没有登录前只适合本机使用。

### 16.5 外部 ID 混淆与加密令牌（2026-09-19 修订第 44 条，用户选择 A1+B2+全覆盖）

| 项 | 稳定规则 |
|---|---|
| 编码组件 | 后端 `auth/ExternalIdCodec`：加盐、最短 8 位、去除 0/O/1/I 等易混字符；同一数字 ID 编码结果稳定且彼此不同 |
| 覆盖资源（外部表现一律为字符串） | 文档、思维导图、同步任务、题目、题目生成任务、PDF 导入任务、AI 助手会话与消息、`/api/auth/me` 用户 id、SSE 事件载荷中的 id、409 冲突返回的 `activeJobId` |
| 不处理 | 思维导图节点 ID（`node_xxx`）、题目关联用 `nodeIds`（本就是随机字符串）；页面路由 `/index`、`/ai` 等 |
| 编码边界 | Controller 收到路径 id 先解码，再做归属校验；响应 DTO 中主键统一输出编码字符串；Service / Repository / 实体 / 后端日志内部仍用数字 Long |
| 非法外部 ID | 空、超过 64 字符或解码失败一律按 **404** 处理，与“资源不存在”返回完全一致，避免攻击者据此判断资源是否存在；同时 `log.warn` 记录资源类型和截断后的外部 ID（禁止打印盐值/密钥） |
| 配置 | 盐值取 `app.security.external-id.salt`（开发默认值写 application.yml，生产用环境变量覆盖）；**不新增表、不加 Flyway 迁移、不改实体字段** |
| 登录令牌 | JWE 紧凑序列化（RFC 7516），`alg=dir`、`enc=A256GCM`，JDK 自带 `javax.crypto` 实现，不引第三方库；内容密钥 = SHA-256(`app.jwt.secret`)；TTL 仍 7 天；解密失败/过期按 401 处理 |
| 兼容性切换 | 旧的明文 JWS 令牌、直接用数字拼接口地址的旧前端立即失效；用户需重新登录一次；不提供数字 ID 与外部 ID 互转接口 |
| 前端 | 资源主键 TS 类型全部按不透明 `string` 使用；localStorage 中的当前文档、活动同步任务、AI 当前会话直接存外部字符串，不再 `Number()` 转换 |
| 安全定位 | 混淆 ID 只负责“不暴露自增顺序、提高猜测成本”，**不是访问控制手段**；真正的越权防护仍由 OwnershipGuard 按登录用户归属拦截（非本人资源 404）；JWE 只解决令牌内容机密性，XSS 等前端安全仍需按常规防护 |

3. 点击导出 PNG 时临时展开全部节点（紧凑模式下也临时放开深度 3 的显示边界，仅用于本次导出），等待 ELK 重新布局和 `fitView` 完成后截取 `.react-flow` 根容器（自动排除缩放控件、官网署名和连接点），输出白底、2 倍像素的 PNG；
4. 导出期间临时隐藏节点上的增/改/删、展开折叠按钮并禁止编辑；导出成功或失败后都恢复用户原本的折叠/展开状态；
5. 动画播放、同步任务锁定、导图不存在或正在生成时禁用“导出 PNG”；空内容笔记仍允许导出 .md；
6. 导出失败时在页面状态栏给出错误提示，控制台打印错误，不影响笔记、导图和后端数据。

验收标准：

- 点击“导出”能下载 `<笔记标题>.md`，内容与左侧编辑器一致；标题包含非法字符时自动替换，不报错；
- 点击“导出 PNG”能下载 `<笔记标题>.png`，图片包含导图全部层级节点和连线（含紧凑模式下平时被收起的深层节点），白底清晰，图片中不出现节点操作按钮；
- 导出结束后画布恢复导出前的折叠状态，导图数据、版本、手动坐标均不变化；
- 同步/动画期间导出按钮置灰；没有导图时不能导出 PNG；
- 不新增数据库表、Flyway 脚本、后端接口和 DTO；后端代码无改动。
