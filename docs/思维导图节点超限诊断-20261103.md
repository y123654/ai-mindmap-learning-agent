# 思维导图节点超限诊断：248 > 200（2026-11-03）

> 输入：`D:\filedown\Chrom\复杂Markdown示例2-Agent智能体知识.md`（5,287 字符，317 行）
> 报错：`单次同步新增节点 248 个，超过上限 200 个（§9.4）`
> 结论：**不是文本太长，是文档"太宽"；现有三级裁剪只裁深度、不裁宽度，所以完全没起作用。重试也不会成功。**
> 实施方案已落盘：`docs/思维导图节点预算与折叠实施方案-v1.0.md`（节点预算 + 折叠，2~3 人日）。

---

## 1. 248 是怎么算出来的（逐项对账）

对源文件做结构统计：

| 结构 | 数量 | 是否生成节点 |
|---|---:|---|
| H1（根） | 1 | 是 |
| H2 | 8 | 是 |
| H3 | 23 | 是 |
| 一级列表项（`- `） | 180 | 是，每项一个节点 |
| 普通段落 | 36 | 是，每段一个 AI 节点 |
| **合计** | **248** | 与报错完全一致 |

也就是说：

- 标题合计 32 个（1 + 8 + 23）；
- 列表项 180 个，**全部是同一缩进层级**（没有嵌套）；
- 段落 36 个；
- `32 + 180 + 36 = 248`。

### 为什么"三级裁剪"没救下来

`MindMapDepthCap.decide()` 的触发条件是"预计新增 > 100"，这份文档 248 > 100，**裁剪确实触发了**。
但它的过滤规则是：

- 标题：只保留 H1–H3（这份文档没有 H4+，32 个全保留）；
- 列表：只保留**一级缩进**的项（`indent == 1`）——这份文档 180 项全是一级缩进，**全保留**；
- 段落：只保留挂载深度 ≤ 3 的（36 个全保留）。

所以裁剪后的数量仍然是 248，再撞上 `MindMapOperationValidator.MAX_NEW_NODES_HARD = 200`，整批操作不发布。

**一句话：这是一份"宽文档"（同一层很多并列项），不是"深文档"；三级裁剪是按深度裁的，对这种结构无效。**

### 为什么重试没用

这是确定性校验：同样的输入、同样的规则，每次都会算出 248。MQ 重试只会重复失败。
错误文案里的"重试"是误导，应该改成"请拆分文档 / 精简结构"。

## 2. 源文件的结构问题

这份示例的列表是"伪层级"：

```markdown
- 感知
- 接收用户输入
- 读取文件或数据库
...
- 思考
- 理解任务目标
...
```

`感知 / 思考 / 行动 / 记忆 / 反思` 是分组标题，后面的项是子项，但 **Markdown 里没有缩进**，解析器只能把它们全部当成 H3 下的同级列表项，于是 180 项 → 180 个节点。

如果手工把子项缩进 2 格：

```markdown
- 感知
  - 接收用户输入
  - 读取文件或数据库
```

解析器会正确建出父子层级；**但三级裁剪只允许一级缩进**，二级项会被整批丢弃，用户会看到"内容少了一半"。所以"只加缩进"不是解，必须同时改裁剪规则。

## 5. 方案 D 的代码设计（给实施会话）

### 5.1 新增节点预算器

新增 `MindMapNodeBudget`（`mindmap` 包）：

```java
BudgetResult apply(List<ValidatedOperation> ops, MindMapGraph current, int cap);
```

步骤：

1. 统计固定节点：根 + H1–H3 + 段落 AI 节点（这些优先保留）；
2. 剩余预算 = `cap - 固定节点数`；
3. 按 H3 分组统计一级列表项数量，按比例分配剩余预算（每节至少保留 2 个）；
4. 每节保留前 K 个列表项作为节点；
5. 被裁掉的列表项，按顺序拼成文本放进"保留的最后一个节点"的 `summary`（≤500 字符）；
   如果超过 500，追加一个 `补充（N 项）` 子节点，summary 继续放；
6. 最终 `addCount ≤ cap`；在 `change_summary` 里加 `foldedCount`，前端提示"已折叠 N 项"。

### 5.2 接入点

`SyncEngine.prepare()` 里，在 `filterMergedOperations` 之后、`validate` 之前调用：

```java
if (capDecision.active()) {
    mergedOperations = nodeBudget.apply(mergedOperations, currentGraph, MAX_NEW_NODES_HARD);
}
```

### 5.3 错误文案

校验失败时不要再写"重试"，改成可执行信息：

```
文档结构过宽：标题 32 个 + 一级列表 180 个 + 段落 36 个 = 248 个节点，超过单次上限 200。
请拆分文档，或开启"精简模式"后再同步。
```

### 5.4 测试

- 用本文的 248 节点结构做 fixture：应用预算后 `addCount <= 200`；
- 180 个列表项 → 被折叠项的文本出现在 summary 或"补充"节点；
- 折叠后 `validate` 通过、不抛 `VALIDATION_FAILED`；
- 现有 100 节点以内的文档行为逐字节不变；
- 上限配置化后，200/300 两档都有用例。

### 5.5 配置

```yaml
app:
  mindmap:
    max-new-nodes: ${MINDMAP_MAX_NEW_NODES:200}   # 方案 C 用
    fold-enabled: ${MINDMAP_FOLD_ENABLED:true}    # 方案 D 用
```
